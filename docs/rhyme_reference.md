# 韻リファレンス（韻ロジック・意味ルール・エンジン構成の正典）

CLAUDE.md から切り出した実装詳細。韻・語彙・フレームを触るときはここを読む。
日付付きの増設履歴・計測値は [dev_log.md](dev_log.md)。

## 韻の方式

- **母音シグネチャ韻**: かなを母音列(a/i/u/e/o)へ変換し、末尾N母音の一致で韻とみなす。ん/っはスキップ、ー は直前母音を延ばす。
  - **拗音は2母音**（2026-09-03 実装確認）: 「しゅ」「きょ」などの小書き仮名は、前の仮名の母音＋小書き仮名の母音として数える。例: 酒母（しゅぼ）=iuo、原酒（げんしゅ）=eiu、きょうかい=iouai。手計算で sig3 を出すときの最大の罠。
- 3母音コアを基本に、KREVA的に4〜5母音の多母音一致まで深掘り。
- 「語尾そろえ(endRhyme)」「両句末が韻語=ソリッド(AABB)」「deepSetで長い共通末尾を優先」の3層。
- 参考: 韻ノート(in-note.com)の基礎＝母音が揃うほど、長いほど良い韻。

### 響き韻（ソフト韻／2026-07-12導入）
「硬い完全一致」でなくても気持ちよく聞こえる韻をロジカルに実現する層。
- ロジック: (1)**最終母音は完全一致**＝行末の響きが韻の錨。(2)手前の母音は音声学的に近いペア **i≈e（前舌）/ u≈o（後舌）** を同クラス扱い（`_NEAR`）。
- 実装: `softKey(sig)` が末尾以外の母音を近似クラスへ畳んだ「響きキー」を作り、`ROLE_SOFT` でバケットを束ねる。`buildVerse`/`usableFrames`/クロス韻は **ROLE_SIG ではなく ROLE_SOFT** で束ねる（＝近似で束なった別sig3の語が同一バースで踏み合う）。
- **同一role内は今も単一sig3が絶対**（辞書設計・harness①）。近似で混ぜたい語は必ず「別sig3の別role」を作り、同じ softバケットに **form違いで同居**させる（fruit/aroma が uou を共有するのと同じ発想）。
- 表示: バケット名は実母音を列挙（例 `iaa/eaa`＝近似束ね）。UIの「単語韻:-」に出る。
- 実例（意味も近い＝気持ちよい）: 生酛(ioo)×酒母(iuo)／精米(iai)×掛け米(eai)／新酒(iiu)×原酒(eiu)／のびやか(iaa)×なめらか(eaa)。

### グラデーション韻（ソフト韻の上位層／2026-07-13導入）
「硬い韻を基本に、足りない時だけ緩める」段階方式。語彙拡張の第1歩＝まず器を広げる（①エンジン改修）。
- ロジック: 基本は3母音の深い韻(`ROLE_SOFT`)。`forcedKey`(キャラ跨ぎ)以外で、**2母音キー(`ROLE_V2`＝ROLE_SOFTの末尾2母音)に広げると実際に候補フレームが増える時だけ、確率50%で「2母音の緩い韻」に器を広げる**。
- 効果の理屈: 3母音だと痩せキャラ(酒米/清酒酵母/乳酸菌)の同韻プールは9語前後→2母音に緩めると15〜23語。器が太る＝反復が減り選択肢が増え、**語尾(最終母音)は必ず一致**するので緩くても韻として成立。
- 深さは守る: KREVA深化(deepSet)が「4母音以上の大グループ」を優先し続けるので、深い韻があればそのまま深く、無い痩せた所だけ緩める。→ 深さ(響き)は3.2〜3.5を維持したまま反復が下がる。
- `buildVerse` は `{key,disp,fam,wide,lines}` を返す。`fam`=踏みキー(2 or 3母音)、`wide`=緩めたか。harness の韻100%は `softKey(sig3(w)).endsWith(fam)` で判定（tier対応）。表示 disp は wide時 "iai+aai+uai+eai" のように "+" 連結。

### Axis3 3語韻フレーム（3スロット／2026-07-13導入）
フレームを `{a}{b}{c}` の3スロットに拡張。1行に3語の韻を並べる「見せ場」。
- エンジン: フレームに `rc` を追加可。`usableFrames` は rb/rc 全てが `ROLE_SOFT` 一致＋（同一役割が複数スロットなら語数≥スロット数）を検証。`buildVerse` は `used[]` で同一役割の重複を避けて左から充填。`rpk`/`solid`/`endRhyme` を `[abc]` 対応に更新。lint.js も slot 'c'→rc を検査。
- **設計上の要点**: 3スロットは「ソリッド形（両句末＋中間で計3語が踏む）」で作る。`p:"end"` でも buildVerse のソリッド優先フィルタで弾かれるため、両句末が韻語＝solid=true にすること（例 `蔵に舞うは {a}／束ねて動かす {b} と {c}`）。
- **反復ガード**: 3スロットは**そのバケットが10語以上**でないと同語反復が増える。variety(7語)で入れたら酒米rep 14.6%に急増→typeに差替えで0.4%に。追加時は必ず rep.js で確認。
- 導入フレーム: 麹菌 koji×3 と person+koji×2 ／清酒酵母 koubo×3 ／杜氏 type×3 ／乳酸菌 type×3 ／酒米 type×3。実出力は「泡盛酵母/協会酵母/蔵付き酵母」(iouo=4母音一致)、「濃醇/爽酒/芳醇」(全ouiu)、「八反錦/山田錦/雄山錦」等の深い3語韻。
- 3スロを増やすなら10語以上バケット（koji/koubo/type）に限定。

## 意味ルール（R1/R2/R3）── 語×フレームの整合を保証

韻（母音）だけでなく「意味の通る言葉」を担保するための規約。`buildVerse` はスロット `{a}` を
**フレームが指定した役割(`fr.ra`)の語だけ**から選ぶ＝役割が意味の均質グループになっているのが前提。
- **R1 韻**: 役割内の全語が末尾3母音一致（`harness.js` ①で検証）。
- **R2 形の純度**: 各役割に `form`（物/人/産酒/香り/味/果実/工程/掛け声/心意気/様子）を1つ割当。
  役割内の全語がその form でなければならない（例: `mill`=物 に「磨き」(動作)を混ぜない）。form表は `lint.js` の `FORM`。
- **R3 スロット適合**: スロット直前の連接語ごとに許される form を定義（`lint.js` の `RULES`）。
  例:「この/我が/その/蔵の」→名詞系（**様子は不可**＝「この華やか」を弾く）／「実に/どこまでも」→様子のみ（「実に麹菌」を弾く）／
  「熟れた/甘き/香る」→果実・香り／「蒸した/削った」→米(物)／「叫ぶ/みなで/高く」→掛け声／「深き」→味・産酒。
- **運用**: 語やフレームを足したら必ず `node lint.js`。コードで判定できない共起（重複「磨き＋磨いた」等）はビルド時にOpusでレビュー。

## エンジン構成（full B / 単語シグネチャ）

- グローバル `VOCAB`: `{単語:{y:読み, r:役割}}`。
- 起動時に自動計算: `ROLE_WORDS`（役割→語リスト）, `ROLE_SIG`（役割→末尾3母音）→ 自動バケット化。
- キャラ `FIGHTERS`（5体）は `roles`（使える役割）と `frames`（文型テンプレ、{a}/{b}が韻スロット）を持つ。
- `buildVerse(me, rnd, forcedKey)` が 1バケット選択→フレーム選択→語をスロットに差し込み。
- 反復制御: 最小使用回数pickW（同語3回以上を抑制）、役割ペアの鮮度、小バケットは単一スロット行。
- **キャラ跨ぎ韻**: forcedKeyで2キャラが同じ母音バケットを共有して踏み返す。UIに ソロ/キャラ跨ぎ 切替。全10対戦ペアが跨ぎ可能。

## 検証ハーネス

- 検査ツールはこのフォルダに常駐: `harness.js`（韻100%/反復/行末韻率/ソリッド率/平均深さ/ユニーク行/クロス網羅）・`rep.js`（バース内反復）・`lint.js`（R2/R3意味整合）。
- 仕組み: node で `<script>` を DOMスタブ付きeval し数値化。実サンプルもこの方法で生成できる。
- ローカルプレビュー: launch.json の "brew-rap"（python http.server 8731）。

## 語彙拡張の指針

- 味・香り・食感の形容（様子）は awa/hanayaka/nobiyaka のように「同母音・別formの新role」で既存バケットに同居させると、意味を壊さず韻を厚くできる。必ず lint.js に form を登録。
- 香り語は末尾母音がバラける（aromaは実は uou 等）。必ず engine の ROLE_SIG と node で突き合わせてから追加すること。
- 新バケットは4語以上そろえるとソリッド行を入れても同語3回以上は出ない（2語のバケットは単一スロット行のみ）。
- 新roleが1語だと同バケットで反復が出やすい→使用フレームを3本程度に抑制。近似束ねの語を足すときは「バケット内の総語数」を見て反復を確認。
- **構造的な学び**: 日本語は母音が散るため、量産は「散発的な単語」ではなく**接尾語ファミリー**（麹一族oui/〜錦iii/〜酒iiu・uiu/〜やかaaa・iaa/〜酛ioo）を太らせる形でしか効かない。語彙の絶対数より、フレームで魅せる段階。

### Axis1 語彙拡張パイプライン（2026-07-13）
pykakasi をscratchpadのvenv(`venv_kks`)に導入し、DB `domain_terms_from_llm2.txt`(2845語)を一括読み付与→app の vowels() 移植でsig3計算→既存role(sig3+form)に合う「ドロップイン候補」を機械抽出。
- 得た知見: **DBは10倍あるがドロップイン歩留まりは低い**。上位はほぼ学術メタ語（官能評価/品質管理等）で、実在の醸造語かつ既存バケットのsig3+form両方に合う語は各バケット数語のみ。pykakasiは熟字訓(生酛→きもと)は正しいが専門語に誤読(吟醸香→×かおり/貴醸酒→×たかし/火入れ→ひいれれ)。**実在性・form一致・読みをAIが校正して確定**する運用が必須。
